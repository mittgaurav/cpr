# Testing the System
The system is tested at three levels, progressing from individual module tests to a full multi-event load test.

## How to Run the Tests
1. **EUnit Tests** — Verify the core functionality of the `ticket_inventory`, `waiting_room`, and `reservation` modules. For each part:
> cd part1/
>
> cat test_cmd.txt

Follow the commands. These commands could be on single node or separate.
> erl
Once the shell comes up - copy paste the remaining commands in it.
For the distributed tests, check whether the command is for ticket server
or the load server. Run the appropriate command to start the node and then
the right set of commands in the shell.

For the rest of the tests, cpr is the starting point
> cd cpr/
>
> erl

```erlang
c("src/ticket_inventory",          [{i, "include"}]).
c("src/waiting_room",              [{i, "include"}]).
c("src/reservation",               [{i, "include"}]).

c("tests/ticket_inventory_tests",  [{i, "include"}]).
c("tests/waiting_room_tests",      [{i, "include"}]).
c("tests/reservation_tests",       [{i, "include"}]).

eunit:test(ticket_inventory_tests, [verbose]).
eunit:test(waiting_room_tests,     [verbose]).
eunit:test(reservation_tests,      [verbose]).
```

2. **Single-Event Load Test (`ticket_load`)** — Start a single ticket event and use a separate Erlang node to generate concurrent load against it. Requires two nodes
- Ticket Node:
> erl -name ticket@127.0.0.1 -setcookie gaga
```erlang
c("src/ticket_inventory",          [{i, "include"}]).
c("src/waiting_room",              [{i, "include"}]).
c("src/reservation",               [{i, "include"}]).
c("src/ticket_sup",                [{i, "include"}]).
c("src/event_sup_sup",             [{i, "include"}]).
c("src/event_sup",                 [{i, "include"}]).
c("src/reservation_sup",           [{i, "include"}]).

ticket_sup:start_link().
{ok, EventId} = ticket_sup:start_event("Disney", "Royal Albert", 100, 20).
ticket_inventory:open_sale(EventId).
ticket_inventory:event_info(EventId).

ets:tab2list(event_sup_registry).
```

- Load Node
> erl -name load@127.0.0.1 -setcookie gaga
```erlang
net_adm:ping('ticket@127.0.0.1').

c("src/ticket_inventory",          [{i, "include"}]).
c("src/waiting_room",              [{i, "include"}]).
c("src/reservation",               [{i, "include"}]).
c("src/ticket_sup",                [{i, "include"}]).
c("src/event_sup_sup",             [{i, "include"}]).
c("src/event_sup",                 [{i, "include"}]).
c("src/reservation_sup",           [{i, "include"}]).
c("src/ticket_load",               [i, "include"]).

{ok, EventId} = ticket_load:get_event_id('ticket@127.0.0.1').
ticket_load:run('ticket@127.0.0.1', EventId, 100, 1).
```

3. **Multiple-Event System Test (`ticket_boot`)** — Start the complete system with multiple events and run load against them simultaneously.

- Ticket Node:
> erl -name ticket@127.0.0.1 -setcookie gaga
```erlang
c("src/ticket_boot", [{i, "include"}]).
ticket_boot:start().
```

- Load Node
> erl -name load@127.0.0.1 -setcookie gaga
```erlang
c("src/ticket_boot", [{i, "include"}]).
ticket_boot:demo('ticket@127.0.0.1').
```

For the distributed load tests, two Erlang shells are required.
The ticket server should be started first and kept running while the load test is executed from the second terminal.

## Test 1 — EUnit Tests

The first level runs the EUnit test suites for the three core components:

- `ticket_inventory_tests`
- `waiting_room_tests`
- `reservation_tests`

Start Erlang with:

```bash
erl
```

Compile the source and test modules, then execute each test suite with `eunit:test/2`.

### Output

The supplied run shows:

```text
ticket_inventory_tests:
  All 11 tests passed.

waiting_room_tests:
  All 15 tests passed.
```

The output also contains warning reports generated by tests that intentionally exercise invalid input and expired-token scenarios. The supplied capture starts `reservation_tests`, but its final output is not included.

---

## Test 2 — Single-Event Load Test

The second level tests the system under concurrent load using one event.

Start the server node:

```bash
erl -name ticket@127.0.0.1 -setcookie gaga
```

Compile the required modules, start `ticket_sup`, create an event, and open the ticket sale.

In a second terminal, start the load node:

```bash
erl -name load@127.0.0.1 -setcookie gaga
```

Verify communication with:

```erlang
net_adm:ping('ticket@127.0.0.1').
```

A successful connection returns:

```text
pong
```

Then retrieve the event ID and execute the load test with `ticket_load:run/4`.

### Output

In the captured run, 100 users were admitted:

```text
admitted:             100
completed:             58
cancelled:             22
expired:               20
failed:                 0
insufficient_tickets:   0

tickets_total:         100
tickets_sold:           58
tickets_reserved:        0
tickets_remaining:      42
```

This exercises the reservation lifecycle under concurrent requests while maintaining the final ticket counts.

## Test 3 — Multiple-Event System Test

The final level tests the complete system with multiple events running simultaneously.

Start the ticket node:

```bash
erl -name ticket@127.0.0.1 -setcookie gaga
```

Then run:

```erlang
c("src/ticket_boot", [{i, "include"}]).
ticket_boot:start().
```

This starts three events in the supplied test configuration:

```text
Sonu Nigam    — Wembley
Disney        — Royal Albert
Arijit Singh  — O2 Arena
```

In another terminal, start the load node:

```bash
erl -name load@127.0.0.1 -setcookie gaga
```

Then execute:

```erlang
c("src/ticket_boot", [{i, "include"}]).
ticket_boot:demo('ticket@127.0.0.1').
```

---
I have avoided using rebar3 or other packaging tools to keep things simple. Similarly, avoided testing against software upgrade to keep things simple.

---
The three tests therefore cover the system progressively: **unit-level correctness → single-event concurrent load → full multi-event system load**. The detailed raw terminal output for each test can be included directly below its corresponding section for reproducibility and debugging.
